# ParTuT

Магазин в Telegram: бот и мини-приложение к нему. Витрина, корзина, доставка по
городам, монеты и розыгрыши, склад, отзывы, панель продавца.

Работает одним процессом на Render, база — Postgres (Neon). Локально тот же код
поднимается на SQLite, без единой настройки.

## Запуск

```bash
brew install python@3.11                              # если его ещё нет
/opt/homebrew/opt/python@3.11/bin/python3.11 -m venv venv
venv/bin/pip install -r requirements-dev.txt
cp .env.example .env          # вписать свой BOT_TOKEN

venv/bin/python run.py        # бот и сайт разом — как на хостинге
```

Порознь, когда правишь что-то одно:

```bash
venv/bin/python -m partut.web.server     # только сайт
venv/bin/python -m partut.bot.handlers   # только бот
ROLE=web venv/bin/python run.py          # то же, но как на хостинге
```

`ROLE` (`all` / `web` / `bot`) решает, что делает процесс. Сейчас всюду `all`:
бесплатный тариф даёт один процесс, и бот с сайтом делят его — падение одного
роняет оба. Разделение готово заранее и включается переменной, а не правкой
кода.

**Токен для локальной работы берите подставной.** С настоящим токеном локальный
запуск шлёт настоящие сообщения настоящим покупателям — бот один, и он не
знает, что вы «просто пробуете».

## Устройство

```
partut/              пакет: сюда смотрит весь код
  config  cache      основание — ни от кого не зависят
  inputs  paths
  errors             жалобы владельцу в личку
  integrations/      всё, что стучится наружу: Телеграм, хранилище копий
  db/                база: ядро в __init__, куски рядом файлами
  notifications      письма продавцу — общие для чата и сайта
  web/               сайт: server.py — фабрика, остальное — ручки по темам
  bot/               чат: команды и ночные дела
  webapp/            само мини-приложение: разметка, стили, куски кода
run.py               единственная точка входа
tests/               проверки (pytest), см. tests/README.md
tools/               разовые скрипты: восстановление из копии
```

Стрелка зависимостей всегда одна: верхний слой знает про нижний, обратно —
никогда. Это не пожелание, а проверка: `tests/test_architecture.py` считает
круги и не даёт им завестись.

Мини-приложение собирается без сборщика: `partut/web/server.py` подставляет
стили и куски кода в разметку прямо при отдаче. Правишь файл — обновляешь
страницу.

## Проверки

```bash
venv/bin/python tests/run_all.py       # весь набор
venv/bin/pytest tests/ -k заказ        # по имени
venv/bin/pytest tests/ --lf            # только упавшие в прошлый раз
venv/bin/ruff check .                  # линтер
```

Перед выкаткой набор гоняется в четырёх сочетаниях: две базы (SQLite и
Postgres) × два часовых пояса (UTC и Минск). SQLite прячет целый класс ошибок,
а на расхождении поясов заказ, сделанный ночью, однажды записывался вчерашним.
То же самое делает GitHub на каждый пуш.

## Выкатка

Хостинг — Render, настройки в [render.yaml](render.yaml). Секреты вписываются в
панели, а не в репозиторий.

Резервная копия базы уходит раз в сутки владельцу в личку и во внешнее
хранилище. Как разворачивать копию и как проводить учения — в
[tests/README.md](tests/README.md). Учения включают оформление заказа: копия,
по которой магазин только открывается, но не принимает заказы, уже была.
